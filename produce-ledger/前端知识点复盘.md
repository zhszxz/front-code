**分层思想(与真实项目一致)**:

- **视图层(views)**:组织页面、处理交互。
- **组件层(components)**:可复用的 UI 片段,靠 `props`/`emits` 通信,不直接碰数据。
- **数据层(store)**:所有增删改查集中在这里,视图只调用 API。
- **纯函数层(lib/utils)**:业务计算逻辑独立出来,无副作用、易测试。

## 三、核心前端知识逐个拆解

### 3.1 组合式 API:`reactive` / `ref` / `computed`

**三者各自职责**:

| API | 用途 | 项目中的例子 |
|---|---|---|
| `ref` | 包装基础类型 / 独立可变值 | `const toast = ref('')`、`const editingId = ref(...)` |
| `reactive` | 包装对象(表单、状态) | `const form = reactive({...})`、`const state = reactive({...})` |
| `computed` | 由已有状态**派生**出值,自动缓存 | `totalNet`、`canSave`、`myTransactions` |

**核心思想:单一数据源 + 派生状态**。

```js
// 只存原始输入,其余全部 computed 派生,不手动维护中间值
const globalTare = computed(() => Number(form.tare) || 0)
const summary = computed(() => summarize(form.weighings, form.tare, lossRate.value, unitPrice.value))
const canSave = computed(() => !!form.productName.trim() && unitPrice.value > 0 && summary.value.count > 0)
```

这样改动任何一处,所有相关显示**自动**更新,不需要手动同步——这是 Vue 响应式的最大价值。

**为什么 `ref` 在模板里不用写 `.value`**:模板编译器会自动解包,但 **JS 里必须写 `.value`**。

### 3.2 模块级响应式单例 = 一个极简 Store

`store/ledger.js` 里:

```js
const state = reactive({ user: ..., transactions: loadTx() })   // 模块加载时只执行一次

export const myTransactions = computed(() => state.transactions.filter(...))
export function saveTransaction(tx) { state.transactions.push(tx); persist() }
```

**原理**:ESM 模块在应用生命周期内只被求值一次,导出的 `state` 是**同一个对象引用**。所有 import 它的组件共享这一份状态,改它就全局生效。

这就是「不引 Pinia 也能做状态管理」的本质——Pinia 只是在这套机制上加了 DevTools、模块化、类型推导等糖。

### 3.3 组件通信:props 向下、emits 向上、v-model 语法糖

```vue
<!-- WeighingRow 接收对象,不拷贝、直接引用父级的响应式对象 -->
<script setup>
const props = defineProps({
  modelValue: { type: Object, required: true },  // 注意:传的是"对象引用"
  index: { type: Number, required: true },
  globalTare: { type: Number, default: 0 }
})
defineEmits(['remove'])
</script>
```

**关键技巧**:这里传的是**对象引用**而不是值。子组件里 `v-model="modelValue.gross"` 改的是父级 `form.weighings[i]` 的同一个对象,父组件无需额外处理就会同步。

```vue
<!-- 父组件 -->
<WeighingRow v-for="(w, i) in form.weighings" :key="i"
  :model-value="w" :index="i" :global-tare="globalTare"
  @remove="removeWeighing(i)" />
```

### 3.4 路由:hash 模式 + 动态路由复用页面

```js
const router = createRouter({ history: createWebHashHistory(), routes })

{ path: '/record', name: 'record', component: RecordView },
{ path: '/record/:id', name: 'record-edit', component: RecordView }  // 同一个组件
```

- **`/record` 新建、`/record/:id` 编辑**,共用同一个 `RecordView`,靠路由参数区分模式:

```js
const editingId = ref(route.params.id ? String(route.params.id) : null)
const initialTx = editingId.value ? getTransaction(editingId.value) : null
```

- **hash 路由**的 URL 形如 `http://host/#/history/xxx`。`#` 后面的部分不会发给服务器,因此**纯静态托管**(nginx 直接服务目录)也能正常刷新/直达,不需要 nginx 配 `try_files` 回退(虽然本项目也配了,属锦上添花)。
- `router.push`(新增一条历史记录)vs `router.replace`(暂存后把 `/record` 替换成 `/record/:id`,避免返回键回到重复的新建页)。

### 3.5 列表渲染与 `:key`

```html
<div v-for="tx in myTransactions" :key="tx.id" class="card tx-card">
```

- **`:key` 要稳定唯一**(用 `tx.id`),Vue 靠它做 diff,复用/复用错组件。
- 项目里 `WeighingRow` 用 `:key="i"`(下标)——**这里其实是个隐患**:删除中间一行时,下标整体前移,Vue 会复用错位的组件实例。当前场景因为整行对象是引用传递、没有内部本地状态,所以没出 bug;但**真实项目里更推荐给每「称」一个稳定 id**。这是个值得记住的反面例子。

### 3.6 条件渲染 vs 守卫

`App.vue` 用 `v-if` 做了一个极简「登录门」:

```html
<AppHeader v-if="currentUser" />
<router-view v-if="currentUser" />
<WelcomeView v-else />
```

没登录就渲染欢迎页,登录后渲染主体。真实项目里这通常由**路由守卫**(`router.beforeEach`)或后端鉴权实现,这里是最简演示版。

### 3.7 表单与移动端输入体验

```html
<input class="input" type="number" inputmode="decimal" min="0" step="0.01" v-model="modelValue.gross" />
```

三个真实项目常用的移动端细节:

1. **`inputmode="decimal"`**:手机上自动弹出带小数点的数字键盘,而不是全键盘。
2. **输入框字号 ≥16px**:避免 iOS Safari 聚焦时自动放大页面(浏览器规则:字号 <16px 会触发缩放)。
3. **隐藏 number 的上下箭头**:CSS 里 `::-webkit-outer-spin-button / inner-spin-button { -webkit-appearance: none }`,并配合 `input[type=number]{ -moz-appearance: textfield }`(Firefox)。

> 注意:`type="number"` 的 `min`/`step` 只影响原生校验和步进箭头,**并不能阻止用户手输负数或超范围**,所以业务逻辑里必须自己做校验(本项目的 `isValidWeighing` / `canSave` 就是)。

### 3.8 浮点数陷阱与整数精确计算 ⭐

这是本项目最有价值的知识点之一。

**问题**:`0.1 + 0.2 === 0.30000000000000004`,因为 JS 数字是 IEEE 754 双精度浮点,十进制小数无法精确表示。

**本项目方案:整数最小单位运算,展示时再除回来**。

```js
// 计算层全部用"钱"(0.01斤)和"分"(0.01元)的整数
export function toInt(x) { return Math.round((Number(x) || 0) * 100) }

export function netQian(w, gQ) { return grossQian(w) - effectiveTareQian(w, gQ) }

// 折损:总净重钱 × (1000 − 折损%×10) / 1000
export function afterLossQian(netQianVal, lossPercent) {
  const l = Math.round((Number(lossPercent) || 0) * 10)
  return Math.round((netQianVal * (1000 - l)) / 1000)
}

// 总价分 = 折损后钱 × 单价分 / 100
export function priceInFen(sellableQian, unitPrice) {
  return Math.round((sellableQian * toInt(unitPrice)) / 100)
}
```

**要点**:JS 整数在 `2^53` 内是精确的;把「加/减/乘」都放在整数域,只在最终展示时 `/100`。这与真实记账/电商系统「金额用分存储」是同一个套路。

## 四、真实开发中的常用技巧 / 范式

### 4.1 纯函数计算层 + 单一汇总函数

`utils.js` 全是**纯函数**(输入确定、无副作用、不碰 DOM/storage),业务规则集中:

```js
export function summarize(weighings, globalTare, lossPercent, unitPrice) {
  // ...整数计算...
  return { count, gross, tare, net, sellable, price, /* 及整数中间量 */ }
}
```

三个视图(记账/历史/详情)复用同一个 `summarize`,**保证口径一致**——这也是「DRY」原则的体现:计算公式只写一份。

### 4.2 localStorage 持久化 + 数据迁移(向后兼容)

```js
function loadTx() {
  let txs = JSON.parse(localStorage.getItem(TX_KEY)) || []
  // 老数据没有 deleted/status 字段 → 补默认值
  // 老数据用 grossJin/grossLiang 双字段 → 迁移成单字段 gross
  for (const t of txs) {
    if (t.deleted === undefined) t.deleted = false
    if (!t.status) t.status = 'done'
    if (hasOwn(t, 'tareJin')) { t.tare = toJin(t.tareJin, t.tareLiang); delete t.tareJin }
    // ...
  }
  return txs
}
```

**范式**:数据格式会随需求迭代(斤/两双字段 → 单字段小数;无状态 → 草稿态),**读取时做一次幂等迁移**,老用户数据不丢、不崩。真实项目的「数据库 migration / schema 版本化」是同一思想。

### 4.3 多用户数据隔离

```js
export const myTransactions = computed(() =>
  state.transactions.filter((t) => t.userId === state.user && !t.deleted)
)
```

所有查询都强制带 `userId === 当前用户`,做到「各看各的账」——后端系统里这叫**租户隔离(tenant isolation)**,前端 demo 里用同样的过滤逻辑演示。

### 4.4 软删除 / 回收站

```js
export function trashTransaction(id) { t.deleted = true; t.deletedAt = Date.now() }  // 标记
export function restoreTransaction(id) { t.deleted = false; delete t.deletedAt }      // 恢复
export function purgeTransaction(id) { state.transactions.splice(i, 1) }               // 真删
```

**范式**:删除操作**不直接物理删除**,而是打标记。这样能实现「误删可恢复」,是几乎所有真实系统(邮件、网盘、后台)的标准做法。

### 4.5 草稿态(status 字段)

交易有 `status: 'draft' | 'done'`:

- 「暂存」→ `status='draft'`,留在当前页继续编辑;
- 「完成」→ `status='done'`,跳转历史;
- 历史列表给草稿打「草稿」标签,可继续编辑。

**范式**:用状态字段区分「进行中」和「已完成」,而不是为草稿建单独的表/集合。

### 4.6 编辑复用新建页(route 参数 + 预填)

`RecordView` 同时服务新建和编辑:

```js
const form = reactive({
  productName: initialTx?.productName || '',
  weighings: initialTx?.weighings?.map(w => ({ ...w })) || [emptyWeighing()],
  // ...
})
```

用 `?.`(可选链)和 `??`(空值合并)优雅处理「编辑时有值 / 新建时用默认」两种分支。

### 4.7 Toast 轻提示(不引库)

```js
const toast = ref('')
let toastTimer
function showToast(msg) {
  toast.value = msg
  clearTimeout(toastTimer)                 // 连续触发时重置计时
  toastTimer = setTimeout(() => (toast.value = ''), 2000)
}
```

配合一个 `position: fixed` 的 `.toast` 元素和 CSS 动画。这是「不引组件库也能做轻量反馈」的最小实现。

### 4.8 表单校验:用 computed 而不是提交时再查

```js
const canSave = computed(() =>
  !!form.productName.trim() && unitPrice.value > 0 && summary.value.count > 0
)
// 按钮直接 :disabled="!canSave"
```

校验结果也是「派生状态」,实时驱动按钮禁用态,用户不用点保存才知道哪里没填。

### 4.9 无效数据不污染结果 + 样式提示

毛重未填、或去皮后净重 ≤0 的「称」:

- **计算上**:`isValidWeighing` 过滤,不参与汇总;
- **交互上**:给该行加 `invalid` 类(红框 + 红色标签「不计入」);
- **保存上**:只保存有效称。

**范式**:坏数据「隔离但不报错」,通过视觉反馈引导用户修正。

### 4.10 移动端响应式与设计令牌

```css
:root {
  --bg: #f5f5f7; --card: #fff; --text: #1d1d1f;
  --accent: #0071e3; --radius: 20px; --shadow-card: ...;
}
```

- **设计令牌(CSS 自定义属性)**:颜色/圆角/阴影集中定义,改一处全局生效,是「苹果风」能保持统一的原因。
- **响应式断点**:`@media (max-width: 560px)` 下卡片收窄、汇总条改竖排。
- **毛玻璃**:`backdrop-filter: saturate(180%) blur(20px)` 做粘性导航和底部汇总条。
- **刘海屏安全区**:`padding-bottom: calc(14px + env(safe-area-inset-bottom, 0px))`,配合 `viewport-fit=cover`。

### 4.11 展示型组件(SummaryBar)

```vue
<script setup>
defineProps({ count: Number, totalGross: Number, /* ... */ })
defineEmits(['save', 'draft'])
</script>
```

`SummaryBar` 不碰数据、不碰逻辑,只负责「把传入的数字渲染出来 + 把点击事件抛给父级」。这是**受控组件 / 哑组件**的典型形态,便于复用和测试。

### 4.12 部署:构建产物 + 静态托管

```
npm run build            # 产出 dist/(index.html + assets/带 hash 的 js/css)
tar -czf dist.tar.gz -C dist .
scp dist.tar.gz ubuntu@host:/tmp/...
ssh ubuntu@host "tar -xzf ... -C /var/www/produce-ledger && systemctl reload nginx"
```

- **资源文件名带 hash**(`index-DousR496.js`):内容变了 hash 就变,天然解决浏览器缓存问题(缓存可以设很长)。
- **hash 路由 + 静态 nginx** 无需服务端重写,是前端项目最省心的部署方式之一。

## 五、踩过的坑与取舍

| 坑 | 说明 | 教训 |
|---|---|---|
| **`:key="i"` 用下标** | 删中间行时组件复用错位 | 列表项最好用稳定 id 当 key |
| **`type="number"` 的 min/step 拦不住负数** | 用户能输入负毛重 | 业务逻辑必须二次校验 |
| **浮点精度** | `100 − 0.03`、`0.1+0.2` 的尾巴 | 金额/重量用整数最小单位 |
| **`Math.round(1.005*100)/100` 类四舍五入** | `0.975` 会显示成 `0.97` | 显示折损系数单独按 3 位处理(`fmtLossFactor`) |
| **`Math.round(x*100)` 在 ×100 前要 `Number()` 兜底** | 空串/`undefined` 会出 `NaN` | `toInt` 里统一 `Number(x) || 0` |
| **Vite 开发时批量改文件偶尔缓存旧模块** | 编译产物和源码不一致 | 重启 dev server 强制重编译(开发期问题) |
| **`prompt()` 做批量输入** | 简单但丑、部分 WebView 可能禁 | 正式产品可换成内联弹层 |
| **数据存 localStorage** | 换设备/浏览器不互通 | 要同步就得接后端 |

## 六、可扩展 / 进阶方向

如果想继续用这个项目练手,可以依次加入:

1. **TypeScript**:给 `Transaction` / `Weighing` / `summarize` 加类型,体会类型带来的安全感。
2. **Pinia**:把 `store/ledger.js` 迁移到 Pinia,对比两者的差异与 Pinia 的价值。
3. **后端 + 接口**:把 localStorage 换成 `fetch` 调 REST API,数据多设备同步。
4. **单元测试**(Vitest):`utils.js` 全是纯函数,天然好测(本项目开发期就是写临时脚本验证的,正式应沉淀成测试)。
5. **组件测试**:`@vue/test-utils` 测 `WeighingRow` 的增删、`SummaryBar` 的按钮态。
6. **PWA**:加 manifest + service worker,支持「添加到桌面 + 离线」。
7. **路由守卫 + 登录态持久化**:把 `App.vue` 的 `v-if` 门换成 `router.beforeEach`。
8. **更多工程化**:ESLint + Prettier、CI 自动构建部署、HTTPS/域名。
